## 1. Product Definition

**Name:** IAMScope
**One-liner:** A multi-tenant workbench for understanding, editing, and auditing IAM policies over time.
**Category:** Cloud security tooling / DevOps.
**Target user:** Cloud engineers, security engineers, platform teams auditing AWS IAM.

**Core value:** Three analysis lenses over one shared data model:
1. **Impact** — diff evaluation results between two policy versions.
2. **Graph** — find multi-hop privilege escalation paths.
3. **Timeline** — reconstruct system state at any past date.

**Differentiator:** Existing tools do one lens. IAMScope does all three from the same collections, backed by MongoDB only, with real-time multi-user collaboration.

## 2. Scope

### 2.1 In Scope (v1)
- Multi-user auth with sessions, password reset, email verification
- Organizations (tenants) with RBAC: owner, admin, member, viewer
- Invitations, member management, API keys
- CRUD for policies, principals, resources, scenarios
- Policy versioning (immutable history)
- Evaluation engine (AWS IAM subset)
- Impact lens (diff between evaluation runs)
- Graph lens (escalation path detection + visualization)
- Timeline lens (state reconstruction + attribution)
- Presence (who's viewing what, live cursors on graph)
- Command palette, keyboard map, density modes, dark/light/system themes
- Change streams + SSE for live updates
- Full audit trail per org
- Docker Compose for local dev, Vercel + Render + Atlas M0 for deploy

### 2.2 In Scope (v2 — build after v1 ships)
- OAuth (GitHub, Google)
- Email provider integration (Resend or Postmark) for real invite/reset emails
- Condition operators: `StringEquals`, `StringLike`, `StringNotEquals`, `ArnLike`, `ArnEquals`, `Bool`, `IpAddress`, `NotIpAddress`
- Permission boundaries (schema-ready in v1, enforced in v2)
- Service Control Policies (SCPs)
- Policy linting (unused permissions, wildcard detection, best-practice checks)
- Scenario suites with tags and bulk execution
- Export/import org policy sets as JSON
- SARIF export for CI integration

### 2.3 In Scope (v3 — future)
- Azure and GCP policy formats (data model is provider-agnostic)
- Real AWS API import (read-only) with credentials
- CI/CD integration (GitHub Action runs regression scenarios on PR)
- Billing and plan tiers
- SSO (SAML, OIDC)
- Self-hosted deployment (Docker image, Helm chart)

### 2.4 Out of Scope (all versions)
- Runtime authorization decisions (IAMScope is a workbench, not an enforcement point)
- Real-time AWS API mutation
- Being a general-purpose policy engine for non-IAM systems

## 3. Non-Negotiable Constraints

1. **MongoDB is the only database.** No Postgres, no Redis, no Elasticsearch, no Neo4j, no Kafka.
2. **Two logical MongoDB databases on one Atlas cluster** (or two clusters in v3): `iamscope_identity` and `iamscope_data`.
3. **Every domain document carries `orgId`.** Every compound index leads with `orgId`. Cross-org reads are impossible without a full collection scan.
4. **`orgId` is derived from the session or API key, never from the request body.**
5. **Backend runs on Render** (Vercel serverless kills SSE). Frontend runs on Vercel.
6. **TypeScript strict mode everywhere.** No `any`. No `@ts-ignore` without a comment explaining why.
7. **WCAG AA minimum.** Every interactive element keyboard-reachable. Reduced motion respected.
8. **Zero layout shift on load.** Skeletons match final layout to the pixel.
9. **Optimistic UI for all mutations.** Rollback with undo toast on failure.
10. **No third-party UI kit defaults.** Radix primitives only; all styling is ours.

## 7. Data Model

### 7.1 `iamscope_identity`

**`users`**
```
_id: ObjectId
email: string (lowercased, unique)
name: string
avatarUrl: string | null
passwordHash: string (argon2id)
passwordUpdatedAt: Date
emailVerified: boolean
emailVerificationToken: string | null
mfaEnabled: boolean
mfaSecret: string | null (encrypted at rest)
status: "active" | "suspended" | "deleted"
preferences: { density, theme, accent }
createdAt: Date
updatedAt: Date
lastLoginAt: Date | null
```
Indexes:
- `{ email: 1 }` unique
- `{ status: 1 }`
- `{ emailVerificationToken: 1 }` sparse
- `{ createdAt: -1 }`

**`sessions`**
```
_id: ObjectId
userId: ObjectId
tokenHash: string (sha256 hex)
activeOrgId: ObjectId | null
userAgent: string
ip: string
createdAt: Date
expiresAt: Date
lastSeenAt: Date
revokedAt: Date | null
rotatedFrom: ObjectId | null
```
Indexes:
- `{ tokenHash: 1 }` unique
- `{ userId: 1, revokedAt: 1 }`
- `{ expiresAt: 1 }` TTL 0 (delete at expiresAt)
- `{ activeOrgId: 1 }`

**`orgs`**
```
_id: ObjectId
name: string
slug: string (unique, url-safe)
plan: "free"
createdBy: ObjectId
settings: { defaultDensity, defaultTheme, accent }
createdAt: Date
updatedAt: Date
deletedAt: Date | null
```
Indexes:
- `{ slug: 1 }` unique
- `{ createdBy: 1 }`
- `{ deletedAt: 1 }`

**`memberships`**
```
_id: ObjectId
orgId: ObjectId
userId: ObjectId
role: "owner" | "admin" | "member" | "viewer"
invitedBy: ObjectId | null
joinedAt: Date
status: "active" | "invited" | "removed"
```
Indexes:
- `{ orgId: 1, userId: 1 }` unique
- `{ userId: 1, status: 1 }`
- `{ orgId: 1, role: 1 }`
- `{ orgId: 1, status: 1 }`

**`invitations`**
```
_id: ObjectId
orgId: ObjectId
email: string
role: "admin" | "member" | "viewer"
tokenHash: string
invitedBy: ObjectId
createdAt: Date
expiresAt: Date
acceptedAt: Date | null
```
Indexes:
- `{ tokenHash: 1 }` unique
- `{ orgId: 1, email: 1 }`
- `{ expiresAt: 1 }` TTL 0

**`api_keys`**
```
_id: ObjectId
orgId: ObjectId
name: string
keyHash: string (sha256)
prefix: string (first 8 chars, display only)
scopes: ("read" | "write" | "evaluate" | "admin")[]
createdBy: ObjectId
createdAt: Date
lastUsedAt: Date | null
expiresAt: Date | null
revokedAt: Date | null
```
Indexes:
- `{ keyHash: 1 }` unique
- `{ orgId: 1, revokedAt: 1 }`
- `{ prefix: 1 }`

**`auth_events`**
```
_id: ObjectId
userId: ObjectId | null
email: string | null
orgId: ObjectId | null
type: string (login.success, login.fail, logout, signup, password.reset, invite.sent, invite.accepted, session.revoked, apikey.created, ...)
ip: string
userAgent: string
metadata: object
timestamp: Date
```
Indexes:
- `{ userId: 1, timestamp: -1 }`
- `{ email: 1, timestamp: -1 }`
- `{ timestamp: -1 }` TTL 15552000 (180 days)

### 7.2 `iamscope_data`

**`policies`**
```
_id: ObjectId

name: string

currentVersion: number

```
`Statement`:
```
sid: string
effect: "Allow" | "Deny"

```
`Condition`: `{ operator: string, key: string, values: string[] }`

Indexes:
- `{ orgId: 1, name: 1 }` unique
- `{ orgId: 1, arn: 1 }` unique
- `{ orgId: 1, deleted: 1, updatedAt: -1 }`
- `{ orgId: 1, "tags.team": 1 }`

**`policy_versions`**
```
_id: ObjectId

```
Indexes:
- `{ orgId: 1, policyId: 1, version: -1 }`
- `{ orgId: 1, createdAt: -1 }`

**`principals`**

## 9. Auth & Multi-Tenancy

### 9.1 Session lifecycle
1. **Signup:** create user, hash password (argon2id), create org, create owner membership, create session, set cookie, emit `auth_event`.
2. **Login:** verify password, create session, set cookie, update `lastLoginAt`, emit `auth_event`. On failure: increment rate-limit counter, emit `login.fail`.
3. **Session validation:** middleware reads cookie → sha256 → `sessions` lookup → check `revokedAt == null AND expiresAt > now` → load user + active org + membership.
4. **Rotation:** on org switch, password change, or role change, issue new session token, revoke old, set new cookie.
5. **Revocation:** `revokedAt = now`. TTL eventually removes.

### 9.2 Cookie config
```
name: iamscope_session
httpOnly: true
secure: true (in production)
sameSite: "lax"
path: "/"
maxAge: 30 days
```

### 9.3 CSRF
- On session create, issue a CSRF token, set non-httpOnly cookie `iamscope_csrf`.
- Frontend reads cookie, sends `X-CSRF-Token` header on all mutations.
- Backend compares header to cookie value. Mismatch → 403.

### 9.4 Rate limiting
- In-Mongo `rate_limits` collection: `{ key, count, windowStart, expiresAt }` TTL 1h.
- Login: 5 attempts per email per 15 min, 20 per IP per 15 min.
- Signup: 3 per IP per hour.
- Password reset: 3 per email per hour.
- API: 600 req/min per API key, 120 req/min per session.
- Exceeded → 429 with `Retry-After`.

### 9.5 RBAC enforcement
Middleware chain per route:
```
requireAuth → requireOrg → requireRole("admin") → handler
```
`requireRole` loads the user's `memberships` doc for `session.activeOrgId` and checks `role` against the required role hierarchy: `owner > admin > member > viewer`.

### 9.6 Tenant isolation
- Every domain route handler receives `orgId` from `req.session.activeOrgId` or `req.apiKey.orgId`. Never from `req.body`.
- Every query and mutation includes `orgId` in the filter.
- Every insert includes `orgId` in the document.
- Compound indexes lead with `orgId`.
- Integration test: user A in org 1 cannot read/write org 2's data even with a valid ID.

## 10. Evaluation Engine

### 10.1 Input
`{ principalArn, action, resourceArn }` scoped to `orgId`.

### 10.2 Resolution order
1. Load principal by ARN (org-scoped).
2. Load all groups the principal belongs to (`groupMemberships` → `principals` of type Group).
3. Collect all policy IDs: principal's `attachedPolicies` + each group's `attachedPolicies`.
4. Load policies (filter `deleted: false`).
5. If principal has a `boundaryPolicyId`, load it. In v2, boundary restricts allowed actions.
6. Load SCPs if v2.

### 10.3 Aggregation pipeline
```
$match principal by orgId + arn
$lookup groups by groupMemberships
$addFields combine direct + group policy IDs
$lookup policies by IDs (deleted: false)
$unwind policies
$unwind policies.statements
$match statements where action matches actions[] AND resource matches resources[]
$group collect matching statements with policy metadata
```

### 10.4 Matching rules
- `actions`: exact match, `*`, or prefix wildcard (`s3:*`, `s3:Get*`).
- `resources`: exact ARN, `*`, or pattern (`arn:aws:s3:::bucket/*`).
- `conditions`: v1 supports `StringEquals`, `StringLike`, `ArnLike`. v2 adds the rest.
- Wildcard matching implemented with anchored regex built from the pattern.

### 10.5 Result logic
1. If any matching statement has `effect: "Deny"` → **Deny** (explicit deny wins).
2. Else if any matching statement has `effect: "Allow"` → **Allow**.
3. Else → **Deny** (implicit).
4. If a boundary policy exists and denies the action → **Deny** (boundary restricts).

### 10.6 Trace
Return every matched statement with `{ policyId, policyName, sid, effect }` so the UI can render the decision path.

### 10.7 Evaluation runs
- On every policy/principal mutation, enqueue a run (in-process queue, debounced 500ms).
- Run evaluates all `scenarios` in the org.
- Store as `evaluation_runs` doc with `triggeredBy`, `causedByAuditEventId`, `results`, `summary`.

## 11. Escalation Engine

### 11.1 Pattern detectors (v1)
1. `iam:PassRole` + `lambda:CreateFunction` + `lambda:InvokeFunction`
2. `iam:PassRole` + `ec2:RunInstances`
3. `iam:CreatePolicyVersion` + `iam:SetDefaultPolicyVersion`
4. `iam:AttachUserPolicy` / `iam:AttachRolePolicy` / `iam:AttachGroupPolicy`
5. `sts:AssumeRole` on a role with broader permissions

### 11.2 Algorithm
For each principal in the org:
1. `$graphLookup` over `principals.assumeRoleTargets` up to depth 5.
2. For each reachable target, check if any policy attached to the source principal grants a required action from any detector pattern.
3. If all actions of a pattern are grantable in sequence, record an escalation path.

### 11.3 Storage
Write to `escalation_paths` with `severity`:
- 1 hop → low
- 2 hops → medium
- 3+ hops → high

### 11.4 Invalidation
On any policy or principal mutation, delete `escalation_paths` for affected principals and re-enqueue computation.

### 11.5 API
`POST /graph/escalation { fromPrincipalArn }` returns cached or freshly computed paths.

## 12. Timeline Engine

### 12.1 State reconstruction at time T
For each entity type:
- **Policies:** latest `policy_versions` where `createdAt <= T` per `policyId`.
- **Principals:** latest `audit_events` with `action: principal.*` where `timestamp <= T`, or current state if no history.
- **Resources:** same as principals.
- **Memberships:** reconstruct from `audit_events`.

### 12.2 Caching
In-process LRU keyed by `(orgId, T rounded to minute)`. Invalidated on any mutation in the org.

### 12.3 Events endpoint
`GET /timeline/events?from=&to=` returns `audit_events` in range, grouped by type for the scrubber markers.

### 12.4 Attribution
`GET /audit/attribution?scenarioId=&before=:runId&after=:runId`:
1. Load both runs.
2. Find the scenario result delta.
3. Find `audit_events` between the two runs' `snapshotAt`.
4. Filter to events targeting policies/principals referenced in the trace.
5. Return the most likely cause with confidence.

## 13. Change Streams & SSE

### 13.1 Watcher
- Watch: `policies`, `policy_versions`, `principals`, `resources`, `scenarios`, `evaluation_runs`, `escalation_paths`, `presence`.
- Use `fullDocument: 'updateLookup'`.
- On `policies` / `principals` change: invalidate `escalation_paths`, enqueue re-evaluation.
- On any change: emit SSE event `{ collection, op, orgId, documentId, timestamp }`.

### 13.2 SSE endpoint
```
GET /api/events
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```
- Validate session.
- Register client in in-memory registry keyed by `orgId`.
- On event from watcher: fan out only to clients with matching `orgId`.
- On client disconnect: remove from registry.
- Heartbeat comment every 20s to keep connection alive.

### 13.3 Frontend
- `useSSE` opens an `EventSource` to `${VITE_API_URL}/api/events`.
- On message: invalidate relevant TanStack Query keys based on `collection` and `documentId`.
- Reconnect on error with exponential backoff (max 30s).
- On org switch: close and reopen.

## 18. Error Handling & Observability

- **Backend:** every error goes through `errorHandler` → structured JSON `{ error: { code, message, details? } }` + request ID.
- **Frontend:** `ErrorState` component for query failures with retry. Toast for mutation failures with undo.
- **Logging:** pino on backend, structured JSON, request ID correlation.
- **Audit:** every mutation writes `audit_events`. Errors during mutation still write `audit_events` with `metadata.error`.
- **No external APM.** All observability is in-Mongo.

## 24. Conventions

- **Branching:** trunk-based. `main` always deployable. Feature branches `feat/`, `fix/`, `chore/`.
- **Commits:** Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`).
- **PRs:** require typecheck + lint + tests + a11y pass.
- **Code style:** Prettier (2 spaces, single quotes, trailing commas), ESLint with `@typescript-eslint` strict.
- **Naming:** `camelCase` for variables/functions, `PascalCase` for types/components, `SCREAMING_SNAKE` for constants, `kebab-case` for file names except React components (`PascalCase.tsx`).
- **Imports:** absolute from `@/` in frontend, `@/` in backend. Shared packages via `@iamscope/*`.
- **No default exports** except React pages.
- **No `any`.** Use `unknown` + narrowing.
- **Errors:** always typed. `Result<T, E>` pattern for service functions that can fail expectedly.

## 26. Definition of Done (v1)

The project ships when, on the deployed Vercel + Render + Atlas stack:

1. New user signs up, creates org, invites second user, second user accepts.
2. Both see each other's presence in real time.
3. Both CRUD policies, principals, resources, scenarios.
4. Every policy edit creates version + audit event + evaluation run.
5. Impact lens diffs any two runs with word-level JSON diff.
6. Graph lens returns escalation paths, renders with semantic zoom, highlights paths on hover, shows live cursors.
7. Timeline scrubber reconstructs state, snaps to events, shows live diff preview.
8. Attribution links scenario deltas to causing audit event.
9. Mutation in one tab updates other tabs in same org within 2s; other orgs receive nothing.
10. RBAC enforced: viewer can't mutate, member can't delete, admin can't delete org, owner can.
11. API keys authenticate and respect scopes.
12. Every interaction keyboard-reachable; command palette covers navigate, create, evaluate.
13. Every mutation optimistic; failures roll back with undo toast.
14. WCAG AA passes; reduced motion respected; ARIA live announces SSE.
15. Lighthouse 95+ all metrics; zero layout shift.
16. Seed produces working demo org from clean DB.
17. README documents local and deployed setup.

## 29. What You Must Not Do

- Do not introduce a database other than MongoDB.
- Do not use JWT for sessions.
- Do not read `orgId` from request bodies.
- Do not skip indexes on new collections.
- Do not use a component library's default theme.
- Do not use `any` in TypeScript.
- Do not add a feature not in the current phase.
- Do not deploy the backend to Vercel.
- Do not commit secrets.
- Do not ship a mutation without an audit event.
- Do not ship a route without RBAC.
- Do not ship a UI without keyboard support.
